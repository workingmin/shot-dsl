# 技术可行性与实施路线

## 结论

“黑白线条 3D 动态分镜预演”技术上可行，且与当前项目的确定性时间轴、Three.js 播放器和 DSL 编译链路匹配。产品价值来自把纸质分镜里的机位、走位、空间和节奏动态化，而不是提高角色或渲染的写实度。

建议继续使用 Three.js。切换 Godot 会获得更完整的动画编辑器和离线渲染能力，但会重写现有 Web 编辑器、Parser、Scene IR 集成和时间轴交互；当前 MVP 的物理需求不足以覆盖迁移成本。

## 输入模型

输入层记录分镜脚本设计，不记录每帧 JSON。外部输入可以是 ShotDSL、表单或未来的可视化编辑器，内容包括：

- 场景时长、fps 和随机 seed；
- 人物、代理道具、空间参照物和初始状态；
- 镜头位置、焦段、目标、运动与切换；
- beat 的时间范围、意图、焦点和连续性要求；
- 人物动作、注视、道具附着和接触约束；
- 位置、旋转、缩放、可见性和相机参数关键帧；
- 随时间显示的分镜文字标注。

编译后形成 Scene IR：连续属性进入 track，镜头切换、动作、注视、附着、IK 和标注进入 event。播放器按任意时间直接求值，因此无需保存每一帧。

## 运行时原则

1. 走位和道具移动由关键帧轨道驱动，保证导演意图可控。
2. 角色大动作使用统一骨架的 Animation Clip。
3. IK 只校正手部触物等局部接触，不承担完整人体运动生成。
4. 刚体不是权威时间源；掉落、抛掷等效果以后也应烘焙为可 seek 的轨道。
5. 相同 Scene IR、seed 和时间点必须得到相同状态。

## 线稿渲染

纯 `wireframe` 会暴露模型三角拓扑，不符合传统分镜阅读习惯。当前单一渲染管线采用：

```text
浅色无纹理实体
+ 人物外轮廓
+ 静态几何折线
+ 轻量接触阴影
+ 地面空间网格
```

当前 `OutlineEffect` 足以验证方向。质量增强阶段应改为 depth + normal 屏幕空间轮廓，并建立不同分辨率、远近景和蒙皮动作下的视觉回归，重点解决线宽变化、细部丢失和动画闪烁。

## 视频导出

当前实现使用 `canvas.captureStream` + `MediaRecorder` 输出 WebM，导出循环按场景 fps 推进绝对时间轴。它适合验证完整产品闭环，但存在实时等待、编码器差异和 WebM 格式限制。

正式导出管线建议：

```text
固定输出分辨率和 fps
→ 按帧号计算绝对时间
→ Three.js 离屏渲染
→ WebCodecs 编码 VideoFrame
→ WebM/MP4 mux
→ 可选音频轨合成
```

服务端 FFmpeg 可作为浏览器不支持 WebCodecs 时的降级方案。

## MVP

首期包含：

- 10～30 秒短场景；
- 1～4 个中性代理人物和基础空间道具；
- idle、walk、run、crouch、talk、reach、look-around、fall；
- fixed、lookAt、follow、orbit 相机和硬切；
- 位置、旋转、缩放、可见性及相机参数关键帧；
- gaze、attach、IK 和时间段文字标注；
- 播放、暂停、拖拽、PNG 和 WebM 导出；
- 一种稳定的黑白线稿风格。

首期不包含拟真角色、材质库、环境 preset、武器、粒子、表情、战斗专用机位、物理仿真和 Agent workflow。

## 风险

| 风险 | 影响 | 缓解 |
|---|---:|---|
| 代理人物轮廓难以读懂朝向 | 高 | 无脸但保留人体体块；统一比例；近景避免过广焦段 |
| 动作 Clip 与走位速度不匹配 | 高 | 允许 speed 调整；后续增加步速诊断和脚底 IK |
| 拖拽与顺序播放结果不同 | 高 | 所有轨道与约束按绝对时间求值；重复 seek 像素回归 |
| 轮廓动画闪烁 | 中高 | 稳定线宽、抗锯齿、depth/normal 后处理和截图回归 |
| 浏览器视频导出差异 | 中 | 能力检测；保留 PNG；后续 WebCodecs/FFmpeg |
| DSL 过早覆盖完整电影语言 | 中 | 只新增能被播放器确定执行和验证的语义 |

## 实施顺序

```text
稳定 storyboard 渲染
→ 镜头与走位编辑体验
→ 标注与节奏审阅
→ 基础动作和接触可读性
→ 固定帧率离线视频导出
→ 可复用代理场景与镜头模板
```
